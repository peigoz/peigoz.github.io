## z —— 快速路径跳转 [zoxide](https://github.com/ajeetdsouza/zoxide)

### 需求分析

1. 进目录太累:

   - `cd ../../..` 一级级敲太烦，深层目录路径又长又容易敲错，每次还得 `pwd` 确认下自己在哪

2. 记不住目录:

   - 经常访问的项目目录，下次想进还得从根目录一层层找，效率太低

### 实现功能

1. `z <关键词>` 直达

   - zoxide 基于 frecency（频率 + 时效）记录你访问过的目录，输入关键字智能匹配，`z blog` 比 `cd ~/xxx/blog` 稳准狠

2. 无缝集成 shell

   - 在 zsh / bash 里直接替代 `cd`，配合 [fzf](https://github.com/junegunn/fzf) 做模糊搜索，历史目录随手就跳

3. 从 z / autojump 平滑迁移

   - 老用户可以直接 import 旧数据，`zoxide init zsh` 一行搞定接入

## zcf —— 零配置接入国产大模型的 AI 代理 [zcf](https://github.com/UfoMiao/zcf)

> 官网：<https://zcf.ufomiao.com/>

### 需求分析

1. Claude Code / Codex 配置繁琐:

   - 环境变量、代理地址、API Key 一个个配，换台电脑又要重来一遍，还容易配错

2. 国产模型接入难:

   - 想用 DeepSeek、GLM 等国产模型，官方客户端并不直接支持，要手动折腾各种中转

3. 多配置切换麻烦:

   - 不同项目想用不同模型（官方 OAuth / API / 代理），每次都要改配置文件

### 实现功能

1. 一键初始化

   - `npx zcf i` 自动完成安装、workflows 配置、API / CCR 代理接入、MCP 配置，全流程一把梭

2. Profile 配置管理

   - 每个模型 / 每种配置存为独立 Profile，通过 `currentProfileId` 快速切换，互不干扰

3. 多代理接入

   - 官方 OAuth 登录、Claude Code Router（CCR）代理、自定义多 API 配置都有，国内模型（DeepSeek、GLM、通义等）轻松接入

4. 更新便捷

   - `npx zcf u` 只更新 workflows，不动你的自定义配置，安心升级

## volta —— 按项目锁定 Node 版本 [volta](https://github.com/volta-cli/volta)

### 需求分析

1. 多项目多版本:

   - 有的项目要 Node 16，有的要 Node 20，手动 `nvm use` 很容易忘记切，一跑就各种报错

2. 团队版本统一:

   - 希望能靠项目本身声明 Node 版本，大家 clone 下来行为一致，不用口头约定

### 实现功能

1. 自动读取 `package.json`

   - 声明 `engines.node` 后，进入项目目录自动切换到对应 Node 版本，无需手动干预

2. 全局工具锁定

   - `volta install` 可以按项目锁定 pnpm / yarn / npm 等工具版本，团队一致性好

3. Rust 编写、速度快

   - 相比 nvm 的 shell 脚本，volta 安装和切换都明显更轻快

## @antfu/ni —— 自动识别包管理器 [ni](https://github.com/antfu/ni)

### 需求分析

1. 一仓库一个包管理器:

   - pnpm / yarn / npm / bun 混着用，命令记不全、容易用错，比如在 pnpm 项目里敲了 `npm install`，装出一堆问题

2. 记不住命令:

   - `npm ci` / `pnpm install --frozen-lockfile` / `yarn install --immutable` 本质是同一个东西，却要记三套写法

### 实现功能

1. `ni` 自动识别

   - 根据项目里的 lockfile 自动选择 pnpm / yarn / npm / bun 执行安装，不用关心底层是谁

2. 命令家族通吃

   - `ni`（安装）/ `nr`（跑脚本）/ `nci`（CI 环境干净安装）/ `nx`（执行 bin）一套语义命令走天下

3. 团队协作友好

   - 队友用什么包管理器不影响你，README 里写 `ni` 就够了

## vite+ —— 统一前端工具链（viteplus） [vite+](https://viteplus.dev/)

> 出品方：VoidZero（Vite 同源团队），Github：<https://github.com/voidzero-dev/vite-plus>

### 需求分析

1. 工具链割裂:

   - 构建用 Vite、测试用 Vitest、lint 用 ESLint、格式化用 Prettier、类型检查用 tsc……一堆工具各管一摊，版本兼容和配置维护成本很高

2. 性能瓶颈:

   - Node 生态里的工具链在大型项目上越来越慢，全栈基建急需提速

3. Node 版本管理也要单独搞:

   - 装完各种工具，还要再折腾一个版本管理器，工具链闭环不了

### 实现功能

1. 一个 CLI 搞定全流程

   - `vp env` / `vp install` / `vp dev` / `vp check` / `vp build` / `vp run` / `vp pack` 一站式覆盖开发到发布

2. 全 Rust 底层、性能碾压

   - 构建比 webpack 快约 40 倍、lint 比 ESLint 快 50~100 倍、格式化比 Prettier 快约 30 倍

3. 集大成者

   - 内置 Vite + Rolldown（构建）、Vitest（测试，含浏览器模式 / 覆盖率 / 类型测试）、Oxlint（检查，兼容 750+ ESLint 规则）、Oxfmt（格式化）、tsgo（类型检查）、tsdown（库打包）

4. 自动管理 Node 版本

   - 自动选择并管理 node / pnpm / npm / yarn / bun 版本，版本管理直接内建

---

这波工具链的野心是把"装一堆工具 + 配一堆配置"的日子终结掉，跟 Vite / Vitest / Rolldown / Oxc 是同一批人在推进，值得长期关注 :rocket:
